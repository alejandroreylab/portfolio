Cómo se hizo esta web

Has encontrado el esquema del circuito. Esta página no aparece en el menú: es el making-of del portfolio, escrito para cualquier persona con curiosidad, tenga o no conocimientos de programación. Si alguna vez has pensado «me gustaría tener una web así pero no sé programar», sigue leyendo: esa era exactamente mi situación de partida en la parte web.

La idea clave: esta web no la ha escrito un programador tecleando código de memoria. La hemos construido conversando con una inteligencia artificial, revisando cada pieza y decidiendo qué se quedaba y qué no. A esa forma de trabajar se le llama vibe coding.

1 · Cómo se creó: vibe coding con Fable 5

El vibe coding consiste en describir en lenguaje natural («quiero una línea de tiempo que parezca un circuito electrónico, con hitos que se enciendan al pulsarlos») a un modelo de IA —en este caso Fable 5, de Anthropic— y que sea él quien escriba el código. Tu trabajo no es programar: es dirigir, probar y corregir, como quien revisa un prototipo en el taller.

El flujo de trabajo real fue este:

  1. Conversar y pedir. Describía a la IA qué quería conseguir, con el máximo detalle posible: estética, comportamiento, a quién va dirigida la web.
  2. Copiar el código a Visual Studio Code. VS Code es un editor de texto gratuito pensado para código. Cada respuesta de la IA se guardaba allí como un archivo (por ejemplo index.html).
  3. Probar en el navegador con Live Server. Una extensión de VS Code que abre la web en el navegador y la recarga sola cada vez que guardas. Así ves al instante el efecto de cada cambio, sin publicar nada todavía.
  4. Corregir e iterar. Si algo no me convencía («la tarjeta se superpone al texto», «esto es demasiado recargado»), se lo contaba a la IA y generaba solo el ajuste necesario. Muchas vueltas pequeñas, no una vuelta grande.
  5. Publicar en GitHub Pages. Cuando todo funcionaba en local, los archivos se subieron a un repositorio de GitHub, que ofrece alojamiento gratuito para webs estáticas como esta.

2 · Consejos si quieres hacer lo mismo

  • Pide poco cada vez. «Cámbiame el color de los botones» funciona mucho mejor que «rediséñame la web entera». Los cambios pequeños son fáciles de revisar y fáciles de deshacer.
  • Describe el resultado, no el código. No necesitas saber cómo se hace una animación; necesitas saber explicar qué quieres que se vea y se sienta.
  • Pide el código comentado en tu idioma. Todos los archivos de esta web llevan comentarios en español que explican qué hace cada bloque. Dentro de seis meses, tu yo del futuro lo agradecerá.
  • Guarda copias antes de cambios grandes. Duplicar la carpeta del proyecto cuesta dos segundos y te permite experimentar sin miedo.
  • Sube tú el archivo real cuando algo falle. La IA no ve tu pantalla: si le pasas el archivo tal y como lo tienes, trabajará sobre la realidad y no sobre una versión antigua de la conversación.
  • Desconfía de la sobreingeniería. A veces la IA propone soluciones más complejas de lo necesario. Si una petición sencilla genera veinte líneas nuevas, pregunta si hay una forma más simple. Casi siempre la hay.
  • Tú tienes la última palabra. La IA propone; tú decides. El criterio estético y pedagógico de esta web es humano.

3 · Cómo está estructurada la web

La web es multipágina: cada apartado del menú es un archivo independiente. Todas comparten la misma navegación, el mismo pie y la misma hoja de estilos, de forma que parecen una sola pieza.

portfolio/ ├── index.html → Portada con el Circuito del Tiempo ├── sobre-mi.html → Trayectoria en formato narrativo ├── proyectos.html → Tarjetas de proyectos, filtrables por rol ├── formacion.html → Formación académica y complementaria ├── competencias.html → Competencias transferibles, con iconos dibujados ├── herramientas.html → Herramientas que uso, filtrables por familia ├── repositorios.html → Fuentes externas de proyectos y archivos ├── contacto.html → Bornes de contacto y terminal de contribución ├── como-se-hizo.html → Esta página (fuera del menú) ├── css/ │ └── estilos.css → Todo el aspecto visual, compartido ├── js/ │ ├── global.js → Comportamientos comunes a todas las páginas │ └── circuito.js → Solo la portada: dibuja el circuito interactivo └── img/ → Fotografías e imágenes de los proyectos

Una decisión importante: no se usa ningún framework (ni React, ni WordPress, ni plantillas). Solo los tres lenguajes básicos de la web. La página carga rápido, no depende de nadie y cualquier archivo se puede abrir y leer con un editor de texto normal.

4 · Los tres materiales: HTML, CSS y JavaScript

Siguiendo la metáfora electrónica de la web, cada tipo de archivo cumple un papel distinto en la placa:

  • HTML — la placa y sus componentes. Define qué hay y en qué orden: títulos, párrafos, imágenes, enlaces, tarjetas. Es el contenido puro. Si abres proyectos.html verás que casi todo es texto legible envuelto en etiquetas como <h2> (título) o <p> (párrafo).
  • CSS — la serigrafía y el acabado. Define qué aspecto tiene todo lo anterior: colores, tipografías, espaciados, cómo se recolocan las tarjetas en el móvil. Aquí vive un solo archivo, estilos.css: cambias un color ahí y cambia en toda la web a la vez.
  • JavaScript — la corriente. Define qué ocurre cuando interactúas: que un hito del circuito se encienda al pulsarlo, que un filtro oculte tarjetas, que un texto se escriba letra a letra. Sin JavaScript la web seguiría viéndose bien, pero estaría «apagada»: todo estático.

Una forma de recordarlo: el HTML es el esqueleto, el CSS la piel y el JavaScript los reflejos. Los tres archivos son texto plano: nada está compilado ni oculto, y por eso cualquiera puede estudiarlos.

5 · Qué elementos dinámicos tiene la web

  • El Circuito del Tiempo (portada). La línea de tiempo profesional dibujada como un circuito con dos ramas en paralelo. Los hitos no están escritos en el HTML: viven como una lista de datos en js/circuito.js y el script los dibuja. Al pulsar un componente, la «corriente» ilumina la pista hasta él y se muestra su ficha. En el móvil, esos mismos datos se muestran como lista desplegable.
  • Pantalla de carga. El «// cargando el laboratorio…» inicial. Se oculta sola cuando la página está lista, con una red de seguridad de 3 segundos para que nunca se quede colgada.
  • Tecleado de cabeceras. La frase verde sobre cada título (como la de esta página) se escribe letra a letra, con cursor parpadeante, imitando una terminal.
  • Aparición al hacer scroll. Tarjetas y bloques entran suavemente cuando llegan a la pantalla, en lugar de estar todo visible de golpe.
  • Halo del cursor. En ordenador, un tenue resplandor sigue al puntero sobre la rejilla de puntos del fondo, como una lupa de taller.
  • Filtros. En Proyectos puedes filtrar tarjetas por rol (docente, formador, gestor) y en Herramientas por familia (IA, fabricación, programación, audiovisual). El filtro solo muestra u oculta: no borra nada.
  • Tarjetas desplegables. Los botones «+» expanden el detalle de cada proyecto sin salir de la página.
  • Terminal de contacto. En Contacto, una ventana de terminal simulada invita a contribuir al laboratorio.
  • Interruptor de movimiento. El más importante: un botón fijo permite apagar todas las animaciones. Y si tu sistema operativo tiene activado «reducir movimiento», la web lo respeta automáticamente y no anima nada. La accesibilidad no es un extra: es parte del diseño.

6 · Cómo se actualiza la web

Un portfolio solo está vivo si crece. Por eso la web está construida en bloques repetibles: añadir contenido nuevo casi nunca exige saber programar, solo copiar un bloque existente y cambiar sus textos. Los propios archivos contienen comentarios (líneas entre <!-- y -->, invisibles para el visitante) que indican qué bloque copiar en cada caso.

Por ejemplo, para añadir un proyecto nuevo se abre proyectos.html, se duplica una tarjeta completa (todo el bloque <article class="tarjeta-proyecto"> … </article>) y se rellenan sus campos:

<article class="tarjeta-proyecto" data-roles="docente"> ... <h3>Título del proyecto nuevo</h3> <span class="curso mono">Mes y año</span> ... </article>

El mismo patrón se repite en toda la web: un curso nuevo es un <li> copiado en Formación; una herramienta nueva, una fila en su familia de Herramientas; un hito nuevo del circuito, una entrada más en la lista de datos de circuito.js. La estructura no se toca: solo se alimenta.

El ciclo completo de actualización es siempre el mismo:

  1. Abrir el archivo en VS Code y copiar/editar el bloque.
  2. Comprobar el resultado en el navegador con Live Server.
  3. Subir los cambios al repositorio de GitHub: en unos instantes, la web publicada se actualiza sola.
Ritmo realista: más vale una entrada nueva cada trimestre que un rediseño heroico cada dos años. El portfolio documenta un camino, no una foto fija.

7 · Decisiones de fondo (lo que no se ve)

  • Estética con significado. El tema «laboratorio nocturno» —placa de circuito, pistas menta, hitos ámbar— no es decoración: cuenta la historia de un ingeniero que derivó su corriente hacia la educación. Elige una metáfora que hable de ti y deja que atraviese toda la web.
  • Un color por rol. Docente, formador y gestor tienen cada uno su color, coherente en etiquetas y filtros. La coherencia visual ayuda a quien te lee a orientarse sin esfuerzo.
  • Móvil primero. Buena parte de las visitas llegarán desde un teléfono. Cada elemento tiene pensada su versión móvil (el circuito, por ejemplo, se convierte en lista).
  • Privacidad. En un portfolio docente, las fotos con alumnado solo se publican con los permisos correspondientes; en caso de duda, mejor la foto del espacio, del material o del resultado.
  • Sin dependencias. Al no usar librerías externas, dentro de diez años estos archivos seguirán abriéndose y funcionando igual.

8 · ¿Quieres montar tu propio laboratorio?

Todo lo anterior es extrapolable. La receta mínima: una idea clara de a quién te diriges y qué quieres demostrar, una metáfora visual propia, un editor gratuito (VS Code + Live Server), un asistente de IA con quien conversar, y GitHub Pages para publicar sin coste. El resto es iteración y paciencia: esta web tampoco salió a la primera.

Y si por el camino te atascas o quieres contarme cómo va tu circuito, ya sabes dónde está el borne de contacto.
